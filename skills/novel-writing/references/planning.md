# 開書與規劃

寫第一章之前、開新卷之前、改大綱的時候讀這份。

## 1. 開書前要問清楚的五件事

寫進 `novel.config.md` 的「基本」一節。作者說不確定，就依題材給兩三個選項讓他挑，不要自己決定。

1. **讀者**：年齡層、在哪裡讀（網站、平台、紙本、遊戲內）、喜歡什麼。
2. **文風**：給一章範本，或描述句長、對話比例、形容詞多寡。
3. **禁區**：不能寫的題材、讀者地雷、參考作品的名稱。
4. **自主程度**：每章都給作者看／每幾章看一次／照大綱自己寫到卷末。
5. **規模**：全書幾卷、一卷幾章、一章大約多長、更新頻率。

## 2. 全書與每卷的大綱

建一份大綱檔（位置寫進設定檔），三層：

- **全書**：一句話主題、結局方向、主要故事線、幾個大轉折落在哪一卷。
- **每卷**：這卷的目標、開頭狀態、結尾狀態、卷末高潮、這卷允許揭開的事。
- **每章**：一行。誰的視角、這章那一件大事、結尾型態。

### 揭露帳本

把會「用掉」的東西列成表：最大的反派、身世或世界的真相、主角能力的上限、主要感情的結果。每一項標「最早第幾卷可以揭開」。一卷原則上只揭一樣大的。寫章時先查帳本，沒到時間的不能揭。

### 進度錨點

每卷開頭在大綱寫一行：本卷第幾章到第幾章、主線應該推進到哪裡。寫每章時算一下目前在卷內的位置，推進比錨點快太多或慢太多都要說明原因，或回頭調整。

## 3. 排大綱時問四個問題

每卷排完、每十章結束時各問一次：

1. 主角的結果是不是自己的選擇換來的？可以借別人的力，但關鍵選擇和後果要在主角身上。
2. 主角該拿到的回報，有沒有被配角、機構或巧合白白拿走？
3. 有沒有提前用掉揭露帳本裡還沒到時間的東西？
4. 讀者之前被許下的期待，這段有沒有給進展？有沒有用新謎團、新地圖去躲舊的承諾？

四題都過就照寫。有一題勉強但能靠鋪墊、交換、代價補上，先補再寫。補不上就改大綱。

## 4. 一章的拍子表

寫正文之前先列拍子，每拍一兩句：

```
1. 開場：誰、在哪、想要什麼
2. 阻力：什麼擋住他
3. 轉折：多了什麼資訊或變化
4. 那一件大事
5. 後果：關係、處境、資源怎麼變
6. 收尾：用哪一種結尾型態
```

一拍只寫一個場景的進展，不要一拍跨好幾天。拍子少於四個，這章可能太空；多於八個，可能塞了兩章的事。

## 5. 節奏選項（在設定檔選）

- **結尾**：`rotate`（預設，結尾型態輪替，不強制懸念）或 `hook`（每章結尾留鉤子：疑問、危機、轉折三選一，適合平台連載）。
- **檔位**：每章標慢、中、快。快檔（主線突破）之後下一章要是慢或中。
- **故事線輪替**：列出主要故事線與「每幾章至少出現一次」。網文常見分法是主線 55–65%、感情線 20–30%、世界觀線 10–20%，只當參考。
- **事件冷卻**：把章的主要事件分類（衝突、羈絆、勢力經營、風土、危機升級）。同一類當主事件後，隔一兩章再用；每五章至少要有一次羈絆或風土。適合長篇，短篇可以不開。

## 6. 開頭三章（選用）

給需要在前幾章留住讀者的作品：

- 第一章五百字內讓讀者知道主角是誰、要什麼、哪裡不對。
- 第一章結束前出現第一個主動選擇。
- 前三章各有一個小兌現，第三章結尾給出全書的大問題。

## 7. 改大綱

1. 作者明確說要改，才改。寫出要改什麼、為什麼。
2. 列出受影響的範圍：哪些已寫章節、哪些伏筆、事實登記表的哪些條目、揭露帳本。
3. 先改大綱和登記表，再改已寫章節，最後交代下游（翻譯、已發布版本）。
4. 改完把整條影響鏈再走一次自檢第 2、3 節。
